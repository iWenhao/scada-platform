## 功能特性

### 可视化编辑
- 拖拽式组件放置
- 框选/Shift 多选，支持批量移动、删除、复制粘贴
- 画布缩放/平移（空白处拖拽平移，滚轮以指针为中心缩放）
- 组件选中/变换
- 吸附对齐（网格吸附 + 拖拽对齐参考线）
- 标尺与小地图
- 撤销/重做操作
- 画布尺寸自定义
- 亮色/暗色主题切换
- 2D / 2.5D 渲染风格：工程级设置（工具栏切换，随工程保存），`2d` 为平面线条稿、`25d` 开启面基光照；预览页只读跟随——**改风格后须发布才在运行端生效**（预览默认加载发布版，`?source=draft` 看工作副本）

### 工业组件库

组件库分三个 Tab：**最常使用**（按拖入画布次数自动列出前 12 个高频组件）、**通用组件**（基础图形 / 图表 / 通用设备 / 装饰）与**行业组件**（综采 / 主运输 / 主通风 / 洗选 / 热力 / 电厂 / 化工 / 水处理 / 电气 / 管道）；共 14 个分组、177 种内置组件（两个数字与下列各分组括号内的数量同取法：`getAllComponents()` 按 `group` 分组统计，括号数字相加 = 177）。标题右侧提供**跨 Tab 搜索**（匹配组件名 / 类型 / 分组显示名，大小写不敏感），命中的 Tab 自动激活并在标签上标出圆点；自定义组件与设备模板不设常驻 Tab，只经搜索触达。悬停卡片右上角出现**红色 ×**，二次确认后把用不到的组件移出组件库（内置组件是隐藏，画布上的实例不受影响，可在标题右侧的恢复入口找回；自定义组件与设备模板是真删除）。

### 实时状态监控
- 自定义状态规则（区间判断、逻辑运算）
- 组件颜色/动画响应
- 数据绑定

### 管道连线
- 端口拖拽连线，自动吸附目标最近端口
- 直线/折线/曲线三种路径算法
- 流动动画效果
- 元素移动后连线自动跟随

### 多数据源支持
- WebSocket 实时推送（支持断线自动重连）✅
- HTTP 定时轮询（失败自愈，自动重试）✅
- OPC UA（经 WebSocket 网关接入，NodeId 映射）✅
- MQTT（over WebSocket 浏览器直连 Broker，无需网关；主题即设备，payload 支持扁平变量表或统一格式；写值发布到 `<前缀>/<设备>/set`）✅
- 模拟数据（开发调试，22 台内置设备）✅

### 图层管理
- 背景层/管道层/设备层/标注层
- 可见性/锁定控制
- 图层排序

### 多画面与工程管理
- 单工程多画面，左侧导航切换，画面可增删、重命名、排序
- 首页（项目管理）新建 / 重命名 / 复制 / 删除 / 导入导出工程
- 自动草稿与正式保存分离；撤销/重做栈跨画面共享

### 点表、历史与写值
- 点表管理：集中登记变量（数据类型 / 量程 / 单位 / 读写属性），组件按点位绑定
- 时序历史入库与趋势图取数，保留期由后端 `HISTORY_RETENTION_DAYS` 控制
- 运行期写值（设定值、操作按钮）：按角色、点表只读属性与量程校验后下发
- 报警记录与历史采样点可导出 CSV

### 报警与通知
- 报警引擎按状态规则产生记录，运行端有报警列表与确认
- 报警外发通知：邮件 / Webhook / 企业 IM 机器人 / 短信（发送端在 `server/notify/`）

### 账号与权限
- 登录鉴权，四级角色 `viewer / operator / engineer / admin`
- 工程存储按用户隔离；登录、写值等关键操作进审计日志

### 自定义组件与设备模板
- 把画布上的组合存为自定义组件或设备模板，跨工程复用（不设常驻 Tab，经搜索触达）

## 交互流程

四条主链路的事件顺序（界面操作细节见 [docs/USER_GUIDE.md](docs/USER_GUIDE.md) §5）：

- **拖入组件**：面板 `dragstart`（带 type）→ 画布 `dragover` 提示 → `drop` 换算画布坐标 → 生成元素入 `canvasStore` → `useHistory.saveState()` → Konva 响应式渲染
- **配置状态规则**：选中元素 → 属性面板 → 状态规则对话框增删改 → 写回 `element.statusRules` → `StatusEngine` 重算 → 画布按优先级换色
- **连线**：源端口 `mousedown` → `mousemove` 更新临时线路径 → `mouseenter` 高亮目标最近端口 → `mouseup` 建连接对象入 `connectionStore` → 渲染并按流量播放动画（元素移动时端点跟随重算）
- **预览**：编辑器保存（后端在线写远程，否则回落 localStorage）→ 工具栏「发布」把工程快照为运行版 → 跳 `/preview?project=`（**默认加载发布版**，无发布版时回落工作副本，`?source=draft` 强制读工作副本）→ 按当前数据源建连 → 数据推送驱动 `StatusEngine` → 只读渲染（禁拖拽/编辑；2D / 2.5D 渲染风格随工程只读跟随）。两个入口有别：编辑器工具栏的「预览」在同标签跳转（带 `?source=draft`，顶栏有「编辑器」返回键）；首页卡片的「预览」是新开标签的独立运行端（读发布版，本标签留在项目列表，顶栏不显示「编辑器」键）

## 快速开始

### 环境要求

- Node.js >= 18（`vite@5` / `vitest@1` 声明的 engines 是 `^18.0.0 || >=20.0.0`；容器镜像用 20）
- pnpm >= 9，**推荐 10/11**——`pnpm-lock.yaml` 是 `lockfileVersion: 9.0`，pnpm 8 读不了它，会当作没有锁文件重装并把锁改写成旧格式；镜像里固定 `corepack prepare pnpm@11`

### 安装

```bash
pnpm install
```

> pnpm v10+ 默认拦截依赖的构建脚本，本项目已在 `pnpm-workspace.yaml` 中声明允许 esbuild、@parcel/watcher、vue-demi 执行构建，直接安装即可。若曾中断安装导致依赖损坏（报 `Cannot find module .../vite/...`），删除 `node_modules` 后重装。

### 开发

```bash
pnpm dev                # http://localhost:5173
```

### 启动存储后端（可选）

```bash
pnpm server             # http://localhost:5174，数据落 server/data/*.json
```

前端经 `/api/storage/*` 访问后端（Vite 已代理 `/api`）；**后端不在线时自动回落 localStorage**，纯前端试用可以不起它。要登录账号、用户隔离、时序历史与报警外发则需要起后端——环境变量与种子账号见 [docs/DEPLOY.md](docs/DEPLOY.md)。改 `vite.config.ts` 代理或 server 路由后需重启 dev server。

所有接口只有一种响应形状：成功 2xx 是 `{ data, meta? }`（值在 `data`，etag、分页统计、写入条数等附属信息在 `meta`），失败是 `{ error: { code, message } }`，成功与否只看 HTTP 状态码。前端唯一入口是 `src/api/client.ts` 的 `apiFetch`，业务代码按 `code`（如 `version_stale` / `key_exists`）分支、不按中文 `message` 分支。完整接口与错误码见 [docs/DEPLOY.md §5.3](docs/DEPLOY.md)。

一份 `DATA_DIR` 只允许跑**一个**后端实例：启动时会抢 `DATA_DIR/.lock`，抢不到就以退出码 1 拒绝启动并说明持锁方是谁。因为写入串行化与账号/会话表都是进程内的，两个实例共用同一目录的后果不是报错而是静默覆盖数据（判活与接管规则见 [docs/DEPLOY.md §5.6](docs/DEPLOY.md)）。

## 组件开发指南

### 新增内置组件

一个组件要能用，得走完「定义 → 注册 → 数据 → 文档」四步，缺一步就会出现「面板里能拖、拖上去是灰的」：

1. **写定义**——在对应分组目录的 `index.ts`（如 `src/industrial/coal/index.ts`）里按 `ComponentDefinition` 导出对象：
   - `type` 全局唯一、英文小写；Mock 设备按 `<type>_1` 命名即可被 `deviceStore.suggestDeviceId()` 自动绑定；
   - `icon` 为 SVG 字符串，`viewBox="0 0 100 100"`，`currentColor` 会被状态色替换；新写设备图元一律按**面基（插画级）**规范，见 [docs/2.5D_ILLUSTRATION_GUIDE.md](docs/2.5D_ILLUSTRATION_GUIDE.md)；
   - `statusRules` 的 `priority` 数字越小优先级越高；`dataBindings` 的首个绑定变量会显示在元素上；
   - 可选字段：`motion`（运转动效，仅有可动件的设备需要）、`capabilities`（属性面板的能力裁剪开关）。
2. **注册进面板**——把定义加进该目录导出的组件数组，由 `src/industrial/panelRegistry.ts` 汇总调用 `registerComponents([...])`（面板、搜索与「最常使用」都从注册表取数，注册一次三处生效；`ComponentPanel.vue` 以副作用 import 该模块触发注册）。**新增分组要动三处**：`src/types/scada.ts` 的 `ComponentGroup` union（类型源头，漏了 `group` 字面量直接过不了类型检查）、`panelRegistry.ts` 的 `BASIC_GROUPS` / `INDUSTRY_GROUPS`（决定落在哪个 Tab）、同文件里的 `groupNames`（分组标题与搜索匹配共用一份，经 `getGroupName()` 对外暴露，本身不导出）。
3. **补模拟数据**——在 `MockDataAdapter` 的 `listDevices()` 与 update 数据里加同名设备。
4. **同步文档**——更新本文件的组件表与 `docs/USER_GUIDE.md` 的设备清单。

运行期动态注册（自定义组件从存储恢复时走这条）直接用注册表 API：

```typescript
import { registerComponent, unregisterComponent } from '@/industrial/registry'
```

### 自定义组件与设备模板（不写代码的那条路）

在编辑器里把画布上的组合存成**自定义组件**或**设备模板**：前者由 `src/industrial/customLibrary.ts` 落存储（键 `scada_custom_components`），后者由 `templateLibrary.ts` 落库（键 `scada_device_templates`），启动时再注册回注册表。两者都与工程数据解耦——属"组件库"，刷新后仍可用；隔离按账号命名空间（远程模式由后端 `u/<userId>/` 完成，本地回落 localStorage 时沿用同一前缀语义）。组件库面板不设常驻 Tab，经搜索触达。

### 最小定义示例

```typescript
import type { ComponentDefinition } from '@/types/scada'

export const MyComponentDefinition: ComponentDefinition = {
  type: 'my-component',
  name: '我的组件',
  group: 'basic',
  icon: '<svg viewBox="0 0 100 100">...</svg>',
  defaultWidth: 80,
  defaultHeight: 80,
  defaultConfig: {},
  statusRules: [],
  dataBindings: [],
  properties: [],
}

// 然后把它加进同目录 index.ts 导出的组件数组，由 panelRegistry 统一注册
```

### 状态规则配置

支持以下条件类型：

- `compare`: 比较运算（>, <, =, >=, <=, !=）
- `range`: 区间判断
- `and`: 逻辑与
- `or`: 逻辑或
- `expression`: 表达式求值

示例：

```typescript
const statusRules = [
  {
    id: 'running',
    name: '运行',
    color: '#00d4aa',
    condition: {
      type: 'compare',
      variable: 'speed',
      operator: '>',
      value: 0,
    },
    priority: 1,
  },
  {
    id: 'high-temp',
    name: '高温',
    color: '#ff4757',
    condition: {
      type: 'and',
      conditions: [
        { type: 'compare', variable: 'temp', operator: '>', value: 80 },
        { type: 'compare', variable: 'speed', operator: '>', value: 0 },
      ],
    },
    priority: 2,
  },
]
```
