## 1. 术语：本项目的「立体」分三类，不要混谈

| 类别 | 立体感来源 | 运行时代价 | SVG 能否精确表达 |
|---|---|---|---|
| 真 3D | 运行时求解投影（WebGL） | 需要渲染引擎 | 不适用 |
| **2.5D 等轴测** | **等轴测/斜切投影 + 明暗分层** | 纯 2D 绘制 | **能**（仿射变换） |
| 图标级伪立体 | 分档透明度 + 描边 | 纯 2D 绘制 | 能，但观感有限 |

### 1.1 判据（一票决定）

问：**投影 / 遮挡 / 剖切需不需要在运行时变化？**

- **不需要** → 走 2D / 2.5D，**不要引入 Three.js**。
- **需要**（转视角找设备、真实前后遮挡、任意剖切、漫游巡检）→ 才用 3D 渲染器；此阶段若仍要等轴测观感，用 `OrthographicCamera`（正交相机）而**不是**透视相机。

### 1.2 投影的数学边界（必记）

- **等轴测 = 平行投影 = 仿射变换**。观察方向 (1,1,1)/√3，三轴等量缩短 √(2/3)≈0.8165，投影轴间夹角 120°；**平行线保持平行、无灭点**。
- **SVG 的 `transform` 只有 2D 仿射**（`matrix` / `translate` / `scale` / `rotate` / `skewX` / `skewY`），因此等轴测可被 SVG **精确**表达。业界同类产品（如图扑 HT）的 2.5D 实现手段之一正是**斜切变换（Skew）**，与本项目同路。
- **透视投影是除以 z 的非线性变换，SVG 表达不了**。不要试图用 SVG 画近大远小。
- 像素画常见的 2:1 比例实为 dimetric（≈26.57° = arctan(1/2)），非真等轴测的 30°，但已成为事实标准——**本项目采用 2:1**。

## 2. 2.5D 场景的两个必备机制

### 2.1 坐标映射（2:1 等轴测）

```
screenX = originX + (gridX - gridY) * tileW / 2
screenY = originY + (gridX + gridY) * tileH / 2 - z
```

- `tileW : tileH = 2 : 1`
- `z` 为离地高度（向上为正）
- 方向直觉：`+gridX` → 屏幕右下；`+gridY` → 屏幕左下；`+z` → 屏幕正上

### 2.2 深度排序（2D 没有深度缓冲，遮挡必须显式排序）

- 深度键：`depth = gridX + gridY`，**升序绘制**（键小者先画，被后画者覆盖）。
- 有高度时：`depth = gridX + gridY + z * 0.01`（同格内高的在前）。
- Konva 落地：按 depth 排序后赋 `zIndex`（或按序 `add()`）。
- 跨多个格子的大型物体，简单排序会产生错误遮挡，需要拓扑排序或 BSP；2.5D 组态场景应尽量避免超格物体。

### 3.2 插画级（需要「看起来像 3D」时）

- **特征**：**连续渐变 + 接触阴影 + 环境参照 + 材质区分**。
- **适用**：重点设备、展示大屏、宣传画面，数量少（个位数到十几个）。

「插画级」的四根支柱，缺一不可：

1. **连续渐变**（不是分档平色）。柱面沿横向走「亮带 → 压暗 → 边缘补光」；顶面用径向渐变。
2. **接触阴影**。物体与地面接触处的暗影——人眼判断「立起来了」最强的线索，也是最容易漏的一条。
3. **环境参照**。地台、等轴测地面网格、相邻物体。孤立单体放在空白背景上，人眼无从建立体积感。
4. **材质区分**。金属用窄高光、哑光用宽柔光、玻璃用半透明。

> **成本事实（不要低估）**：插画级是**绘制工作量升级，不是技术升级**。面怎么切、几何精度、面数与层序都必须人工设计，成本随设备复杂度线性上升。图扑软件公开承认「轴测插画对设计师空间想象能力要求很高，制作难度和时间成本有时高于三维」。
>
> **因此：插画级不要按台手调明暗。** 一律走第 4 节的面基图元 + 光照后处理器。

**两条路线必须分开，别混谈**：

- 作为**画布图元**（要摆几十上百台、要状态变色、要拆件动效）→ 图标级是正确取舍，插画级的成本 × 数量是乘法。
- 要**宣传级「很 3D」的画面** → 最省路径是离线建模 + 正交相机渲染出图，不要用 SVG 硬啃。**中间没有第三条便宜的路。**

### 3.3 基本体面切法（从这几种起手）

具体设备都是下面几种基本体的组合。三条通用规则先立住：

1. **2:1 定死**。所有等轴测方向都满足 `dy = dx/2`：顶面菱形宽高比 2:1，侧面斜边一律 `(+Δx, -Δx/2)`。门缝、鳍片、把手这些细节也必须落在这条斜线上，差一点就能看出「没对齐」。
2. **圆只有两种朝向**。水平圆（顶盖、俯视的圆面）是扁椭圆 `ry = rx/2`；竖直侧圆（端面、法兰、风口）是竖椭圆，`rx ≈ 0.4~0.5 × ry`。斜置法兰按所在轴旋转 `26.57°`（= arctan 1/2），样本见离心泵的斜口。
3. **层序 = 画家算法**。接触阴影最先 → 靠后的面 → 靠前的面 → 棱线与接缝 → 表面细节 → 可动件。阴影必须先画，否则会盖住机身；同一设备拆成多个体块时，先画低处/远处的。

**立方体（箱体）**。控制柜、电机机身、底座都由它派生。`w` = 半宽，`h` = 竖棱长（伪代码，实际填数字）：

```
顶面  polygons="cx-w,cy  cx,cy-w/2  cx+w,cy  cx,cy+w/2"          data-face="top"
正面  polygons="cx-w,cy  cx,cy+w/2  cx,cy+w/2+h  cx-w,cy+h"      data-face="front"
侧面  polygons="cx,cy+w/2  cx+w,cy  cx+w,cy+h  cx,cy+w/2+h"      data-face="side"
上棱  path="M cx-w cy L cx cy-w/2 L cx+w cy"                     data-edge="hi"
前竖棱 path="M cx-w cy L cx-w cy+h"                              data-edge="hi"
下沿  path="M cx-w cy+h L cx cy+w/2+h L cx+w cy+h"               data-edge="lo"
```

参考 `motor` 的机身（`cx=50 cy=34 w=24 h=36`）与 `cabinet`。箱体的顶面不要用 `deck`（`deck` 只给底座台面）。

**竖圆柱（罐、筒体）**。柱身用一条 path 闭合（上下各一条椭圆弧），顶盖另画一个完整椭圆：

```
柱身    path="M cx-r cy A r r/2 0 0 1 cx+r cy L cx+r cy+h A r r/2 0 0 1 cx-r cy+h Z"  data-face="body"
顶盖    ellipse cx cy rx=r ry=r/2                                                      data-face="cap"
顶盖轮廓 ellipse cx cy rx=r ry=r/2                                                     data-edge="hi"
底弧    path="M cx-r cy+h A r r/2 0 0 0 cx+r cy+h"                                    data-edge="lo"
```

参考 `tank`（`r=26 h=48`）。罐身中部可再加一条 `lo` 弧当焊缝；`body` 的四段渐变会直接把圆柱感做出来，不要再给柱身描边。

**竖直侧圆（端面 / 法兰 / 风口）**。竖椭圆 + `cap`，轮廓单独一条 `hi`（`r` = 竖直半径）；要表达「透进去的暗孔」时面改用 `hole`，轮廓仍是 `hi`：

```
<ellipse cx cy rx="（0.4~0.5）×ry" ry="r" data-face="cap" />   端面
<ellipse cx cy rx="（0.4~0.5）×ry" ry="r" data-edge="hi" />
<ellipse cx cy rx="（0.4~0.5）×ry" ry="r" data-face="hole" />  暗孔，见 fan 的出风口
```

**横卧圆筒（卧罐、换热器壳体）**。壳体用 `barrel`，**不能用 `body`**——`body` 的渐变沿 x 走，套上去是「沿长度明暗」，不是「沿圆周明暗」。轴线取 `dy/dx = 1/2`，上下两条轮廓切线相对轴线各竖直偏 `1.1r`（= `r / cos 26.57°`）；两端用二次曲线向外鼓出（碟形封头，比半球的鼓量浅）：

```
壳身    path="M x1 y1 L x2 y2 Q x2+12 y2+9 x2 y2+18 L x1 y1+18 Q x1-12 y1+9 x1 y1 Z"  data-face="barrel"
远端外缘 path="M x1 y1 Q x1-12 y1+9 x1 y1+18"                                          data-edge="hi"
顶切线  path="M x1 y1 L x2 y2"                                                          data-edge="hi"
底切线  path="M x1 y1+18 L x2 y2+18"                                                    data-edge="lo"
环缝    path="M s s-9 Q s+5.2 s+2.6 s s+9"                                              data-edge="lo"
近端法兰 ellipse cx cy rx="2" ry="r+1" transform="rotate(26.57 cx cy)"                  data-face="cap"（另写一条同参数的 hi）
```

- 环缝**只画朝观察者的半个弧**：画成完整椭圆会把背面那半也画出来，看上去像刻在筒体天顶上。
- 斜置法兰的旋转角固定 `26.57°`（竖椭圆的长轴随之垂直于轴线），样本同离心泵的斜口。
- 鞍座、支腿、下接管一律画在壳体**之前**（画家算法），壳体自然会裁掉它们的上半截。
- 成品参考 `heat_exchanger`（轴线 `(22,42)→(70,66)`，`r≈8`，两个鞍座 + 两道环缝 + 五个接管）。

**管段**（小直径管道，不构成整台设备）走 `data-pipe` 的 `base` + `hi` 两条线（`PIPE_BASE` 的描边可被作者显式 `stroke-width` 覆盖），端口用上面的竖直侧圆（样本：离心泵出入口、阀门两端）。

**正对观察者的圆盘 / 球面**。`cap` 铺面 + 同圆心 `hi` 描一圈轮廓 + 下方接触阴影。只铺 `cap` 不描轮廓会像一块平色圆斑，光照在但不立体。

**细节线**。结构细节（门缝、鳍片、把手）用 `data-edge="lo"`，需要更细时在标签上显式写 `stroke-width`（`expandTag` 保留作者属性）；纯装饰（液位虚线、中心线）保留普通 `<path>` + `stroke-opacity`，不要标 `data-edge`，否则会变成抢轮廓的亮线。

**面数下限**：一个箱体至少 3 个面 + 3 条棱线 + 1 道阴影；竖圆柱至少 2 个面 + 2 条棱线 + 1 道阴影。只有 2 个面且没有棱线和阴影的图元，即使光照正确也明显偏平——`annotatedIcons.test.ts` 的完整性断言会直接拦下。

## 4. 插画级的落地写法：面基图元 + 光照后处理器

核心思路：**把光照层自动化**。作者只标每个面的朝向，不写任何颜色与透明度；后处理器按统一光方向展开连续渐变，并注入阴影与管道高光。

### 4.1 作者写什么

只写几何 + 朝向标注（`viewBox` 固定 `0 0 100 100`），N 值全部为 0..100 用户坐标：

```xml
<g fill="none" stroke="currentColor" stroke-width="1.6" stroke-linecap="round" stroke-linejoin="round">
  <ellipse cx="34" cy="61" rx="12" ry="5.5" data-shadow="1"/>
  <path d="M24 28 L24 60 A10 5 0 0 0 44 60 L44 28 Z" data-face="body"/>
  <ellipse cx="34" cy="28" rx="10" ry="5" data-face="cap"/>
  <ellipse cx="34" cy="28" rx="10" ry="5" data-edge="hi"/>
  <path d="M24 60 A10 5 0 0 0 44 60" data-edge="lo"/>
  <line x1="24" y1="40" x2="56" y2="56" data-pipe="base"/>
  <line x1="24" y1="38.4" x2="56" y2="54.4" data-pipe="hi"/>
</g>
```

**作者不写**：`fill` 的具体值、`fill-opacity`、任何 `<linearGradient>` / `<radialGradient>`。写了等于绕过规范，会造成各图元光源方向不一致——这是手工绘画最常见的翻车点。

**立体观感靠「面不描边 + 单独画棱线」**。2.5D 下面会被展开成 `stroke="none"` 的渐变，轮廓由 `data-edge` 承担；如果继续给每个面留描边，出来的就是 2D 线框图（这正是 2026-10-22 第一版被退回的原因）。所以**同一个几何要写两条标签**：一条 `data-face` 铺体积，一条 `data-edge` 勾棱线（见上面 cap 与它的 `hi` 轮廓）。

| 标注 | 含义 |
|---|---|
| `data-face="top"` | 朝上的水平面（顶面），最亮 |
| `data-face="front"` | 朝向观察者左侧的竖直面，中等 |
| `data-face="side"` | 朝向观察者右侧的竖直面（背光面），最暗 |
| `data-face="cap"` | 端面/球面（圆柱顶底、法兰、手轮hub），径向渐变，高光偏左上 |
| `data-face="body"` | **圆柱侧面（立式）**，横向走「暗→亮带→压暗→边缘补光」四段，是体积感最强的一条 |
| `data-face="barrel"` | **横卧圆柱侧面**（卧罐、换热器壳体），竖向走「天顶亮带→向下压暗」；套 `body` 会变成沿长度明暗 |
| `data-face="hole"` | **暗孔**（进风口、管口内部），压到接近背景，不标就会被画成一块中灰圆斑 |
| `data-face="deck"` | **底座台面**，水平但比 `top` 暗一档；用 `top` 会让底座比机器本身还抢眼 |
| `data-face="ground"` | 地台 / 地面，用极低不透明度平填。**画布图元不用**，见 §4.4 |
| `data-edge="hi"` | 受光棱线：状态色细线，勾轮廓与转折 |
| `data-edge="lo"` | 接缝/凹槽：半透明黑压暗（`#000000` 只是「减光」，不算第二种颜色） |
| `data-shadow="1"` | 接触阴影；**位置由作者给出**，样式统一注入。画布上不铺地台，落地感只靠这一道阴影，画立体物体时不要漏 |
| `data-pipe="base"` / `"hi"` | 管道本体 / 管道高光，样式统一注入 |

一条标签只标一种角色：`data-face` 与 `data-edge` 同时出现时，面先抢走 `stroke`，棱线就画不出来。要「填充 + 描边」请写两条标签。

### 4.2 光照 token（一处定义，全图元复用）

`stops` 是 `[位置, stop-opacity]` 序列（配合 `stop-color="currentColor"`）。**改这张表 = 改全局光感**，不要在单个图元里覆盖。

```ts
const FACE_STYLE = {
  top:   { kind: 'linear', x1: 0, y1: 0, x2: 0, y2: 1, stops: [[0, 0.97], [0.55, 0.86], [1, 0.74]] },
  front: { kind: 'linear', x1: 0, y1: 0, x2: 1, y2: 0, stops: [[0, 0.82], [0.6, 0.56], [1, 0.42]] },
  side:  { kind: 'linear', x1: 0, y1: 0, x2: 1, y2: 0, stops: [[0, 0.42], [0.5, 0.27], [1, 0.18]] },
  cap:   { kind: 'radial', stops: [[0, 1], [0.55, 0.8], [1, 0.44]] },
  body:  { kind: 'linear', x1: 0, y1: 0, x2: 1, y2: 0, stops: [[0, 0.34], [0.28, 0.98], [0.6, 0.62], [1, 0.16]] },
  barrel:{ kind: 'linear', x1: 0, y1: 0, x2: 0, y2: 1, stops: [[0, 0.9], [0.16, 0.96], [0.55, 0.62], [0.82, 0.34], [1, 0.14]] },
  hole:  { kind: 'linear', x1: 0, y1: 0, x2: 1, y2: 0, stops: [[0, 0.26], [1, 0.1]] },
  deck:  { kind: 'linear', x1: 0, y1: 0, x2: 0, y2: 1, stops: [[0, 0.62], [0.6, 0.5], [1, 0.38]] },
} as const

/** 立体：面 = 渐变 + 去描边；棱线分亮暗两种单独绘制 */
const EDGE_HI = 'fill="none" stroke="currentColor" stroke-opacity="1" stroke-width="1.2"'
const EDGE_LO = 'fill="none" stroke="#000000" stroke-opacity="0.3" stroke-width="1.4"'
const SHADOW_SOFT = 'fill="url(#lt-shadow)" stroke="none"'   // 硬边椭圆像贴纸，软投影才像落地
/** 平面：面平涂、边界交给描边，棱线还原成线条稿 */
const FLAT_FACE = 'fill="currentColor" fill-opacity="0.18" stroke-opacity="0.85"'
const FLAT_EDGE = 'fill="none" stroke-opacity="0.8"'
const SHADOW_FLAT = 'fill="#000000" fill-opacity="0.32" stroke="none"'
const GROUND    = 'fill="currentColor" fill-opacity="0.05" stroke-opacity="0.22"'
const PIPE_BASE = 'fill="none" stroke="currentColor" stroke-opacity="0.85" stroke-width="4.6" stroke-linecap="round"'
const PIPE_HI   = 'fill="none" stroke="currentColor" stroke-opacity="1" stroke-width="1.3" stroke-linecap="round"'
```

> 明暗方向约定：光来自**左上方**。暗色画布上「亮面 = 更高 `stop-opacity`」。

### 4.3 后处理器

展开是**按标签**做的，不是按属性做的——一条标签可能同时带 `data-face` 与 `data-edge`，逐个属性替换会把同名属性写两遍。核心两点：

```ts
function tokenFor(kind: string, value: string, mode: ViewMode): string | null {
  if (kind === 'face') {
    if (value === 'ground') return GROUND
    if (!(value in FACE_STYLE)) return null   // 拼错的面标签不产出样式，否则会引用不存在的渐变
    return mode === '25d'
      ? `fill="url(#lt-${value})" stroke="none"`   // 面不描边，轮廓交给 data-edge
      : FLAT_FACE
  }
  if (kind === 'edge') return mode === '25d' ? (value === 'hi' ? EDGE_HI : EDGE_LO) : FLAT_EDGE
  if (kind === 'shadow') return mode === '25d' ? SHADOW_SOFT : SHADOW_FLAT
  if (kind === 'pipe') return value === 'hi' ? PIPE_HI : PIPE_BASE
  return null
}

function expandTag(tag: string, mode: ViewMode): string {
  let out = tag
  for (const [annotation, kind, value] of tag.matchAll(ANNOTATION)) {
    out = out.replace(annotation, '')
    const token = tokenFor(kind, value, mode)
    if (!token) continue
    for (const [name, val] of parseToken(token)) {
      if (out.includes(` ${name}="`)) continue   // 作者显式写过的属性优先，且不重复追加
      const tail = out.endsWith('/>') ? '/>' : '>'  // 自闭合标签的结尾是两个字符
      out = out.slice(0, out.length - tail.length) + ` ${name}="${val}"` + tail
    }
  }
  return out
}

function bakeLighting(svg: string): string {
  const body = svg.replace(ANNOTATED_TAG, (tag) => expandTag(tag, '25d'))
  return injectAfterOpenTag(body, buildDefs())   // defs 含 8 个面渐变 + lt-shadow 软投影
}
```

**两条不可省的判据**（都有过真实翻车）：
- 同名属性只能出现一次：`<path stroke-width="2.4" stroke-width="1.2">` 是非法 XML；
- 属性必须插在 `/>` 之前而不是 `>` 之前：`<ellipse ... / fill="...">` 同样是非法 XML。

两种错误在浏览器里的表现都是**设备画成一片空白**（`<img>` 解码失败），类型检查与肉眼 review 均看不出来，由 `src/industrial/annotatedIcons.test.ts` 用真 `DOMParser` 覆盖全部注册组件兜底。

**处理时机**：在图标字符串进入既有渲染管线（`getIconImage()` 的 `currentColor` 单色替换）**之前**执行一次。因为渐变 stop 用的是 `currentColor`，替换后渐变会随状态色整体变化——**换状态色不需要重调光照**。

### 4.4 落地位置与两种风格

实现落在 `src/core/canvas/faceLighting.ts`：`bakeLighting()` 展开渐变、`flattenFaces()` 平涂、`styleIcon(svg, mode)` 按风格分派并缓存。调用点在 `iconImage.getIconImage()` 里，顺序是**先定风格、再替换 `currentColor`**；图片缓存键必须带风格（同一 `type|color` 在两种风格下不是同一个 SVG）。

画布元素分「立体 / 平面」两档，由工程级设置 `viewMode` 决定（编辑器工具栏切换、运行端只读跟随）：

| 风格 | 面的处理 | 效果 |
|---|---|---|
| `25d` | 面展开为连续渐变并**去掉面自身描边**，棱线按 `data-edge` 单独画亮/暗两种，接触阴影用软渐变；`<defs>` 注入片段内部 | 立体观感 |
| `2d`  | 面统一平涂（`fill-opacity 0.18`）并保留描边，棱线还原成同一粗细的线条，接触阴影是硬边黑块 | 平面图，弱化体积 |

**画布图元不使用 `data-ground`（地台）**。地台是为「一整幅插画式画面」准备的环境参照；画布本身已有网格作为地面参照，再给每台设备各铺一块地台只会变成视觉噪音。单台设备用 `data-shadow`（接触阴影）表达「落地」即可，`data-ground` 只在需要整幅插画时使用。

**同理：不要在元素背后铺一块背景色来表达体积。** 那是旧 `depthLayers.ts` 的做法（已删除）——观感必须全部来自图形本身，铺色块与「纯图形」方向冲突，还会在换背景色或状态色时露出方块。

### 4.5 素材导入件：覆盖映射，不改生成文件

`src/industrial/**` 下的 `*.generated.ts` 由 `scripts/import-subunit-assets.mjs` 生成（type ↔ 源文件对应关系见 `scripts/subunit-manifest.json`），**手工改动会在下次重新导入时被整份冲掉**。要升级为面基，在所属 `index.ts` 里对 `buildAssetComponents()` 的产物做一次映射，把面基稿写进 `icon25d`；参考实现是 `src/industrial/water/index.ts` 的 `illustratedAssets`（离心泵、阀门等 14 台），整组覆盖的例子见 `src/industrial/transport/index.ts`（5 台）。

**口径：同姿态重绘**。素材件的面基稿必须与素材原稿**同 viewBox、同摆放角度、同占地轮廓**——只把「线」换成「面 + 棱线 + 接触阴影」，不重新构图、不换视角、不放大画幅。理由有两条：设备在画板上的位置与比例由素材原稿决定，换一套几何等于让所有已摆好的画面错位；默认放置尺寸、内容包围盒（`core/canvas/iconBounds.ts` 按内容收紧）与旋转锚点也都是按原稿算的，重画就得连带改三处。因此覆盖表里**只有 `icon25d` 与可选的 `name`，没有 width/height**，默认尺寸继续用素材自带的值。

```ts
const illustratedAssets: Record<string, { icon25d: string; name?: string }> = {
  // viewBox 与原稿一致（water_pump 原稿即 0 0 81 98）
  water_pump: { name: '离心泵', icon25d: `<svg viewBox="0 0 81 98">…</svg>` },
}

const waterAssetComponents = buildAssetComponents('water', waterAssetIcons, waterAssetMeta).map(
  (def) => {
    const art = illustratedAssets[def.type]
    if (!art) return def
    const name = art.name ?? def.name
    return {
      ...def,
      name,
      // icon 继续是生成文件里的素材原稿：2D 画布与组件面板都读它
      icon25d: art.icon25d,
      // 属性面板的「名称」默认值也要跟着改，否则仍显示素材原名
      properties: def.properties.map((p) => (p.key === 'name' ? { ...p, default: name } : p)),
    }
  },
)
```

画法上的落地方式：原稿的每个矩形/圆柱体在原位置切成 `top/front/side`（顶面向上收一条窄带、侧面向右收一条窄带，**外沿不得越过原稿轮廓**），圆柱端面用 `cap`、内孔用 `hole`、壳体侧面用 `body`/`barrel`，棱线与接缝用 `hi`/`lo`，底部补一枚落在原稿底边的 `data-shadow`。外扩超过原稿包围盒会改变元素的内容包围盒，等于悄悄改了缩放比例。

没进映射表的素材件保持线条稿，两种风格共存（§4.5）。覆盖后的面基稿同样会被 `annotatedIcons.test.ts` 扫到（含「面基稿与原稿同 viewBox」断言），不需要另写用例。

四条容易漏的：

1. **不要覆盖 `icon`**。素材导入件的 2D 必须与导入原稿逐字节一致：`icon` 被 2D 画布和组件面板（`ComponentCard` 直接 `v-html`）共用，面基稿只能进 `icon25d`；两者写反，2D 与面板立刻变成面基线框。手绘图元同样走双源（2026-10-25 起，见 §6 开工流程第 1 条）：原线条稿留在 `icon`，面基稿写进 `icon25d`，与素材件共用同一张覆盖表；2026-10-25 之前迁移的 19 台手绘件是单 `icon` 旧口径（2D 观感为管线平涂，非原线条稿），属历史存量。
2. **viewBox 与尺寸不要动**。同姿态重绘意味着 viewBox 逐字沿用原稿、默认尺寸沿用素材自带值。重画时若发现原稿比例不合理（设备被拉扁等），那是素材本身的问题，改它会连带移动已摆好的元素，应当单独评估而不是在覆盖表里顺手改。
3. **名称要成对改**。只改 `name` 不改 `properties` 里 `key === 'name'` 的默认值，属性面板仍显示素材原名（如「泵」）。
4. **带动效的素材件不能只换 `icon25d`**。`buildAssetComponents` 的转子是按原图分组 `transform` 串当锚点挖出来的（`AssetRotorSpec.anchor`，见 `src/industrial/assetComponents.ts`），覆盖只替换图标、**不会重写 `motion`**——转子片段与圆心仍是旧几何的，轻则与新机身错位，重则按旧 `viewBox` 坐标直接跑到元素外。改造这类设备时二选一：同时重画转子片段并改锚点（§5 第 3 条），或从覆盖结果里去掉 `motion` 明确放弃动效。落地样例是采煤机（`src/industrial/coal/index.ts` 的 `illustratedAssets`）：`coal_shearer_wide` 条目给出两段面基滚筒片段写进 `motion.rotors[].svg25d`，`svg` 保持挖取自素材的原片段——转子与 `icon`/`icon25d` 一样双源，2D 逐字节保持素材原稿，渲染侧按 viewMode 二选一（`elementMotion.getRotorConfigs`）；锚点与圆心沿用 `coalAssetMotion` 不变。`icon25d` 首行放一只不描边定位框（`fill="none" stroke="none"`），把内容包围盒钉满整个 viewBox，与 2D 基图（挖滚筒后 `addFramingRect` 补的定位框）保持同口径，滚筒的坐标映射才不会错位。

## 5. 硬约束（违反即失效）

1. **单色通道**。整套体系只有一个颜色通道：渐变必须写成 `stop-color="currentColor"` + 不同 `stop-opacity`。**引入第二种固定色会与状态变色打架**（`src/core/canvas/elementStatus.ts` 的 `evaluateElementColor()` 只产出一种颜色）。唯一例外是 `#000000`：接触阴影与 `data-edge="lo"` 接缝用它，语义是「减光」而不是「另一种材料」，只允许出现在这两处。
2. **`<defs>` 必须写在片段内部**。图标是先被光栅化成位图的（`src/core/canvas/iconImage.ts` 用 `new Image()` + `data:image/svg+xml`），每个片段独立光栅化，引用外部 defs 会失效。
3. **可动件必须从主图标里挖掉、单独成片段**。位图内部的元素无法单独旋转（见 `src/core/canvas/elementMotion.ts` 文件头说明）。代价是图形定义要写两处，改图必须两处同步，否则出现「静止齿 + 转动齿」重影。
4. **不做透视**。不画近大远小，不画灭点收敛。
5. **线条稿不能直接套用本管线**。`fill="none"` 的线稿没有「面」，`bakeLighting()` 对它无效，要升级为插画级必须先按 §4.1 改写为面基。**迁移是分批进行的**：`styleIcon()` 对不含任何 `data-*` 标注的图标原样返回，因此未迁移的设备在两种风格下观感与改造前完全一致——已迁移（面基）与未迁移（线条稿）可以共存，不会出现「一半正常一半空白」。这是「先做样板批次、再逐步铺开」得以成立的前提。样板批次见 §3.1；素材导入的图元不要手改 `*.generated.ts`，覆盖写法见 §4.5（参考 `src/industrial/water/index.ts` 的 `illustratedAssets`）。
6. **2.5D 场景必须显式做深度排序**（见 §2.2）。
7. **插画级与设备数量是乘法**。画布上要摆几十上百台的图元不要用插画级。
8. **展开后的 SVG 必须是合法 XML**。图标走 `data:` URI 给 `<img>`，按 XML 严格解析：重复属性、把属性插到 `/>` 的斜杠之后，都会让整份文档解析失败、**设备直接画成空白**（不是画成线稿，是什么都没有）。这条由 `src/industrial/annotatedIcons.test.ts` 用真 `DOMParser` 对全部注册组件把关，改 `faceLighting.ts` 后必须跑它。

## 8. 常见错误对照

| 现象 | 成因 | 修正 |
|---|---|---|
| **设备在画布上完全空白** | 展开后的 SVG 不是合法 XML（同名属性出现两次，或属性被插到 `/>` 的斜杠之后），`<img>` 解码失败 | 见 §5 第 8 条，跑 `annotatedIcons.test.ts` 定位到具体 `type` |
| 2.5D 与 2D 看起来没区别 | 面还带着描边（等于线框图），或渐变两端 `stop-opacity` 差太小 | 面必须 `stroke="none"`，轮廓改由 `data-edge` 承担 |
| 底座比机器本身还抢眼 | 底座用了 `top` | 改用 `deck`（水平但暗一档） |
| 进风口/管口像一块中灰圆斑 | 用了 `front` 或 `cap` | 改用 `hole` |
| 图元像「拼色块」，不立体 | 只用分档透明度，没有连续渐变 | 改用面基 + §4.2 光照 token |
| 画了渐变，观感仍平 | 缺接触阴影 | 补 `data-shadow` 椭圆：比物体底部略宽，只让露出的下弦可见 |
| 单台好看，多台像贴纸 | 缺环境参照，或各图元光源方向不一致 | 加地台 / 地面网格；统一取自左上 |
| 换状态色后渐变失效、变成死色 | stop 写了固定色 | 改为 `stop-color="currentColor"` |
| 渐变完全不显示 | `<defs>` 写在片段外，被光栅化切掉 | 把 `<defs>` 移进片段 |
| 出现「静止件 + 转动件」重影 | 可动件没有从主图标中挖掉 | 见 §5 第 3 条 |
| 场景中远处设备挡住近处 | 没有做深度排序 | 按 `depth = gridX + gridY` 升序绘制 |
| 线条稿套用后处理器毫无变化 | 线稿 `fill="none"`，没有面 | 见 §4.5，需先改写为面基 |
| 给图表/挂件加了 `data-face` 却没反应 | 该类型不走图标管线 | 见 §9，这类组件的立体化是另一条路 |

## 9. 适用范围边界：哪些组件到不了这条管线

本规范只管**图标位图**。以下三类不在管辖范围内，不要给它们加 `data-face` / `data-edge`（加了不会报错，但会被静默忽略——最费时间的正是这种「做了没效果」）。

### 9.1 结构性到不了：Konva 侧根本不生成图标位图

`useElementVisuals.getIconImageConfig()` 对这些类型直接返回 `null`（判据在 `src/core/canvas/useElementVisuals.ts:208-216`），`styleIcon()` 一次都不会被调用：

| 类别 | 类型 | 图形实际由谁画 |
|---|---|---|
| ECharts 图表（4） | `chart-trend` `chart-bar` `chart-pie` `chart-radar` | HTML overlay 里的 ECharts 实例 |
| DOM 挂件（9） | `progress-bar` `report-table` `grid-chart` `filter-table` `date` `clock` `video` `iframe` `super-text` | overlay 里的 DOM |
| Konva 原生绘制（5） | `pipe` `display` `command-button` `text` `image`（已设 `imageUrl` 时） | 各自的原生图形：管身 `pipeFlow.ts`、大字文本、圆角矩形+指令文字、文本节点、用户位图 |

前 13 个类型的清单以 `src/core/canvas/overlayTypes.ts` 为唯一来源（Konva 与 `HtmlOverlay.vue` 共用，加新 DOM 组件必须同步它，否则出现「图标重影」或「什么都不显示」）。

**这类组件要做 2.5D，是改 CSS 配色与图表样式，不是改图标。** 反过来也成立：看到某个组件在 2.5D 下没变化，先查它在不在这张表里，再怀疑光照模型。

### 9.2 内容里没有「面」可标：内嵌位图

图标串里是 `<image href="data:image/...">` 时，SVG 里没有几何面、也没有 `currentColor`，光照后处理器无从下手。已知的有：

- `deco_nav`（装饰组「导航」，992×62 横幅截图）——注册表 178 个组件里唯一一个内嵌位图；
- 自定义组件选**「原图内嵌」**方案生成的图标（`src/industrial/imageVectorize/` 的 WebP 内嵌产物）。这类图标本来就不随状态变色，两种风格下观感一致，属预期行为；要变色与立体只能走「矢量描摹」方案。

### 9.3 技术上能标，但不该标

- **平面图形件**（`shape_rect` / `shape_circle` / `shape_triangle` / `shape_hline` / `shape_vline` / 两条虚线）：矩形与横线没有「朝向」可言，硬标 `data-face` 只会得到一块带渐变的矩形。它们走图标管线，所以标了会生效——**生效不代表正确**。
- **要摆几十上百台的图元**：见 §5 第 7 条，插画级的成本与数量是乘法。
- **状态灯**（`status-lamp`）：灯芯的实色就是功能本体（停机灰 / 运行青绿 / 报警红），而面基在 2D 下会把面淡成 0.18 透明，灯芯会失去「亮着」的观感；灯体又是固定灰。保留线条稿，理由见 `statusLamp.ts` 头注释。
- **电气组 14 台简图符号件**（2026-10-25 需求方确认豁免）：`elec_substation_2/3/4/6/7/8/11/12`、`elec_single_phase_transformer`、`elec_current_transformer`、`elec_grounding`、`elec_indicator`、`elec_switch`、`elec_switch_closed`——绝缘子串、双圆符号、接地、开关这类电气简图没有立体形体可标，保持线条稿（组内 8 台立体设备已迁移，见 §3.1 范本表）。
- **其余存量线条稿**：见 §4.5，迁移是分批的，未迁移的在两种风格下观感与改造前一致，不是 bug。存量数会随批次推进变化，取法：注册总数 − `annotated.length` − 本节豁免名单，勿抄旧数。

### 9.4 与类型无关的一条限制：旋转会转走光源

光照烘进位图，而 `rotation` 加在元素 Group 上（`src/core/canvas/CanvasElements.vue:196`）。于是：

- 转 90°，「左上光」变成「右上光」；转 180°，明暗整个颠倒；负 `scale`（镜像）同样镜像光向；
- 运行时**没有**反向补偿，也没有任何检查会拦你。

结论：**面基立体图元按 0° 摆放**。同一画面光源方向一致是 §6 验收清单里的硬性一条，而旋转是破坏它最省事的方式。若确实有横躺的设备（皮带、管道），正确做法是把几何画成横的，而不是旋转一个竖着的图元。
