# 示例工程

`demo-project.json` 是一个可直接导入的完整工程，用来快速看到平台的主要能力，不用从空白画布开始搭。

## 导入方式

首页 → 「导入项目」→ 选择本文件 → 打开即可。

## 里面有什么

**两张画面**（演示多画面与跳转）

| 画面 | 内容 |
|------|------|
| 工艺流程 | 原水箱 → 水泵 → 出水阀，带流动动画的折线连线；液位实时值（数值显示图元）、阀门开度设定（可写值）、跳转到趋势页的按钮 |
| 趋势监控 | 液位趋势（折线，双系列）、水泵运行参数（柱状）、温度占比（饼图）、返回按钮 |

**工程级配置**

- **点表**：4 个点位（液位/温度/转速/阀门开度），带单位、量程与可写标记——阀门开度 `writable: true`，其余只读
- **报警定义**：3 条独立报警（液位过高/过低、水泵压力异常），都配了**死区**与**延时**（如液位过高：>85% 持续 3 秒才报，回差 3% 才恢复）
- **数据源**：内置 Mock，导入即可看到实时数据

## 建议的体验顺序

1. 打开工程 → 预览页，看数值实时刷新、连线流动
2. 点「阀门开度设定」→ 输入 0~100 → 二次确认 → 下发（随后右上角锁形按钮可一键锁写值，审计日志可看到这条记录）
3. 点「→ 趋势监控页」跳到第二张画面，看三种图表；用顶部画面下拉或「上一画面」返回
4. 编辑器里打开「点表管理」看实时点位列表，打开「报警配置」看死区与延时的设置
5. 断开数据源（或把 Mock 停掉）观察：数值变 `--`、约 5 秒后报出「数据源通信 / 链路中断」

## 结构说明

文件为工程导出格式 `version 1.1`（`pages[]` 多画面）。若你手工修改，注意两点：

- 画面跳转用**元素顶层**的 `navigateTo`（值为目标页 id 或 `__back__`），不是 `properties` 里的字段
- 连线必须带坐标点 `points`（至少 4 个数；曲线为贝塞尔采样点）。空数组不会渲染连线

该文件的结构由 `demoProject.test.ts` 在 CI 中校验，改动后跑 `npx vitest run examples` 确认。
