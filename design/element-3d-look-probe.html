立体观感设备图 · 状态变色与部件联动验证

验证一件事：「立体观感」不需要 Three.js，也不需要元素背后的色块——把明暗做进 SVG 图标内部即可。 立体感完全由 currentColor + 不同 fill-opacity 分层表达，因此 现有单色替换管线（svg.split('currentColor').join(color)）原样生效：状态变色自动覆盖机身与可动件。

一、主舞台：状态与转速联动

机身与截齿共用一个状态色通道；截齿是独立节点，绕各自滚筒圆心旋转，速率由驱动值决定。

二、状态变色：同一图标，四种状态

四张图来自同一个 SVG 字符串，仅替换颜色后重新光栅化并缓存（键 type|color）——与生产实现一致。

三、部件联动：停机 / 中速 / 满载

右下角数值是换算后的角速度。clamp(degPerUnit×speed, 110, 400) 的上下限是防频闪护栏：转速过高会被显示器采样成静止或倒转。

四、部件级独立变色：机身与刀头各持一色

独立控色的粒度 = 拆分粒度。位图路线下，能单独控色的范围正是「被拆成独立 <img> 的范围」——与可动件用的是同一套机制。 下面三张卡片的机身与刀头走不同颜色通道，且刀头仍按各自的速率转动。

五、皮带联动（输送机）

实体带面无法用位图局部平移，改用推进 dashoffset 的竖线标记表达输送方向与带速——与管道流动同一手法。

七、观感对照：分档透明度 vs 插画级绘制



  同一题材（等轴测地台 + 两座储罐 + 一段管道），只换绘制技法。
  左是上面几节用的「分档透明度」——三块平色，读作拼色块；
  右改用连续渐变 + 接触阴影 + 等轴测地面网格 + 统一光源：柱面沿横向走
  「亮带 → 压暗 → 边缘补光」，罐底加接触暗影，地面网格提供体积参照。
  两边颜色都仍走 currentColor，状态变色照旧生效（含渐变的 stop-color）。






八、摊平成本：面基图元 + 光照后处理器



  插画级的成本卡在「明暗要逐台手调」。这一节把光照层自动化：
  作者只给每个面标一个朝向（data-face="top|front|side|cap"），不写任何颜色与透明度；
  后处理器按统一光方向展开连续渐变，并把接触阴影、管道高光按统一样式注入。
  状态色仍走 currentColor，所以这套自动化不影响变色与拆件动效。
  左是作者的原始输入（只有轮廓），中/右是后处理器输出。
