二、组件矩阵受上方开关影响，可逐项切换观察

横向设备（采煤机、掘进机、汽轮机）是现状方案的受害重灾区；纵向设备（阀门、储罐）反而接近合理；方形设备（泵、电机）两者差别不大。这正是「正方形等比适配」的典型特征——它只对方形符号友好。

运行 / 开启 / 正常 停止 / 关闭 / 低液位 警告 / 过载 未知 / 停机 无状态规则（默认色）

三、状态表达同一个泵，三种状态

现状只用线色一个通道，运行与停止在远处看只差一个描边颜色，报警态没有权重差异。建议把状态同时落到底色、描边与线色三个通道，报警/严重态再以加粗描边提升权重。

四、2D 与 2.5D

2.5D 由 depthLayers.ts 的地面投影、侧面体积与顶面高光构成，与主体是「同一层叠加」关系。建议的新形态必须与它共存，因此底色与描边的观感要在两个视图下都成立。

五、边缘情况缩小到 0.6× 时是否还能读

组态画面里元素常被缩放。现状方案在 0.6× 下图标只剩一个缩在下方的小线稿，名称条与数值胶囊反而挤占了主体空间——因为 getLabelHeight 返回的是固定 16/26px，不随元素缩放。建议方案要求分区高度按元素缩放并设上下限，且当图形可用高度不足时自动撤掉数值角标、再撤名称条，把空间优先让给图形本身。

  1. 需要你拍板的第一件事：底色。建议形态给元素加了淡底色，视觉上会从「裸线稿」变成「有块面的符号」——信息量更高，但与当前深色画面的轻盈感不同。若你希望保持轻盈，可只保留「状态色描边 + 长宽比适配 + 名称底栏」，去掉底色。
